# nx2android checkpoint triage

Use this skill to bring Android runtime checkpoints to a new nx2android title or diagnose a failure during capture, cold restore, or a subsequent in-game save. [简体中文](SKILL.md)

Read `docs/CHECKPOINT_ONBOARDING.en.md` in the target nx2android worktree for collection commands, searchable log messages, source locations, and acceptance checks. If the guide and implementation differ, use the source for the host build under investigation.

1. Identify the package, game and SDK Build IDs, host build, data pack, device and driver, scene, and build that created the snapshot. Locate the failure in build or startup, manual capture, slot publication, cold restore, resumed gameplay, or in-game save commit. Start with the evidence already supplied. When a detail is missing, explain which conclusion depends on it.
2. Inspect the complete stderr logs from the capture and restore processes separately. Each cold launch rotates `log.txt` to `log.prev.txt`. Report the last successful operation, earliest identifiable failure, original return code, and corresponding call. Several capture summaries of the form `scene … result=` can carry the same earlier error. The final restore `result=1` can hide the underlying code. If the evidence identifies only an interval, name the smallest controlled comparison or the call whose return value would narrow it down.
3. Choose the smallest change supported by the evidence. Add a row keyed by the actual main or SDK build when the established mechanism and existing table cover the difference. For an engine-specific host override that must be released at a known point, check the existing interface in the module that owns the state. When a new resource state must survive process recreation, implement capture and restore together in the owning backend module. Report mixed builds, storage failures, stale snapshots, and expected in-game save conflicts separately.
4. Diagnose or implement the fix according to the request. Cite the observed log lines and source locations, explain what they establish, identify outstanding alternatives, and record verification results. Distinguish device probe results from the target game's end-to-end check: save a checkpoint, cold-restore it, exercise gameplay, write an in-game save, cold-start normally, and load that save. If the task covers log analysis only, mark unexecuted checks as pending.
